## 0. 当前基础与最终体验

已有基础：Flutter选图/编辑/抖动预览代码、Android release包、腾讯云API/MQTT服务、ESP联网及下载刷屏固件。此前已通过临时SSH转发完成真实云端刷屏和摄像头核对；这不代表iPhone或公网直连已经通过验收。

2026-10-20进度：公开仓库和首次iOS云端Release构建已完成，已下载核验真实IPA并在Ubuntu写入私人连接配置；公网443/8883、脚本刷屏及白天摄像头核对均通过。待完成iPhone签名安装及实测、手机实际发起的摄像头闭环。实际记录见[安装说明](ios-installation.md)和[验证记录](verification.md)。

最终用户体验：安装后的App首次打开即自动连接自己的相框；相册选图→双指缩放/拖动/任意角度旋转→固定5:3裁剪→确定生成六色抖动预览→点击刷新→查看结果。用户不填写服务器地址或令牌、不登录项目账户，日常使用不连接电脑。

产品架构沿用现有实现：Flutter共用iOS/Android代码；屏幕800×480、六色；手机生成192000字节面板数据，HTTPS上传，云端以MQTT通知ESP，ESP经HTTPS下载校验后驱动屏幕，再回报任务结果。保留单设备单任务、幂等、防重复刷屏及BUSY超时。服务端公开API保持现有接口，不为安装流程增加注册登录功能。

## 3. 构建与安装包交付

### 公开仓库准备

- 本地已建立Git仓库。首次发布前检查待发布文件，排除`.private/`、私有Wi-Fi/云端头文件、签名密钥、配对资料、构建目录和当前私人APK/固件。
- 将测试用照片替换为程序生成的测试图，修正公开仓库中指向仓库外文档的链接；保留已有第三方许可。
- 公共iOS包不包含云端访问令牌；随包提供空的连接配置资源及CA公钥证书。App支持从该资源读取安装时配置，普通用户无需接触令牌或填写连接表单。
- Ubuntu下载公开IPA后，由本地脚本校验SHA-256和构建元数据，从现有`.private/`读取云端地址及App访问凭证，只替换归档内的连接配置资源，再签名安装。此自用安装包仅保存在本地，不重新上传到公开仓库或公开构建产物。签名在配置写入后进行，覆盖修改后的资源。
- 如果目标仓库已存在，先检查内容并复用合适的仓库，不覆盖已有工作。

### GitHub Actions

- 标准`macos-15` runner，Flutter固定3.38.10、Xcode固定26.2；首次构建记录实际镜像与工具链信息。
- 主分支相关源文件更新或手动触发；静态检查与测试通过后执行`flutter build ios --release --no-codesign`。
- 将生成的`Runner.app`放入`Payload/`，保留目录结构和符号链接打包为`mojian-unsigned.ipa`。使用Release/AOT，让App签名后能独立启动，不依赖调试器或JIT。
- 交付IPA、SHA-256、提交编号、版本号及构建日志；提供GitHub产物下载链接，并下载到Ubuntu私有本地目录。
- 单次构建超时45分钟，同分支取消旧构建；产物最长保留3天、最多最近两份，不配置构建缓存。只使用公开仓库的标准免费runner；账号层面付费预算是否已设为0须在用户账号中核实，不声称脚本已修改账户账单设置。
- Apple账号、密码、证书私钥不提供给Actions；Actions不登录Apple账号。

### IPA怎样安装到手机

可以交付下载链接和本地IPA文件；未签名IPA本身不能在iPhone文件App中点开安装。首版具体流程：

1. 将iPhone用数据线接到Ubuntu，解锁并信任电脑。
2. Ubuntu配置`usbmuxd`和官方来源的iloader，首次验证当前稳定版2.3.10。
3. 用户在iloader本机窗口登录Apple账号并完成必要验证。
4. 本地脚本将私有云端连接配置写入下载的IPA；随后导入iloader，工具处理个人开发证书、设备/应用注册、描述文件及嵌套框架签名，并经USB安装。
5. 如手机提示，按系统要求启用开发者模式、信任个人开发者；从桌面启动“墨间”。
6. 记录实际Team、Bundle ID和描述文件到期时间，后续保持同一账号及应用标识覆盖安装。验证更新后Keychain连接配置仍保留。

助手负责工程、CI、产物下载核验、安装环境和错误诊断；用户负责账号登录验证及手机上的信任/确认操作。iloader为第三方工具，与iOS26.7.1及Apple当前认证通道的兼容性必须实机验证，不能在首次安装前保证成功。

免费个人描述文件有效期7天，每台设备最多3个此类App。按已选方案，每5～6天连接Ubuntu续签；没有代码改动时复用本地IPA，无需重新跑CI。保留本地最新IPA，避免远程产物过期影响续签。

## 4. 安装后连接云端

用户安装后打开App，即自动读取安装流程写入的云端地址及内部访问凭证，安全保存并查询设备状态；首次启动也不要求输入令牌、服务器地址或登录账号。后续启动和联网恢复均自动连接。项目CA公钥证书随App提供，无需让用户关闭TLS校验。

访问令牌只是App请求中携带的内部服务器凭证，与Apple/GitHub账号无关，不属于普通用户操作流程。公开源码/公开IPA保留空配置；提供给本人手机的安装包由Ubuntu自动补齐私有配置。开发诊断入口可以保留，但不得成为正常使用的前置步骤。

安装成功不等于联网链路已验收。当前检查结果：

- `ssh tencent`正常；`elink-api`、`mosquitto`、`nginx`均为active。
- 2026-10-20用户保存CVM入站安全组规则后，Ubuntu公网HTTPS443健康检查及鉴权查询成功、MQTTS8883证书验证通过，ESP恢复公网在线。
- 公网图像下载与脚本刷屏已通过，白天实拍对应预览；手机实际操作、Wi-Fi及蜂窝网络仍需分别验收。
- 当前USB列表未发现iPhone；摄像头和ESP串口设备存在。

在iPhone正式闭环前确认：手机可通过HTTPS连接API、ESP通过MQTTS在线且可HTTPS下载、App展示相框在线。手机可与屏幕处于不同网络；验收包含手机Wi-Fi和蜂窝网络，屏幕继续使用自己的Wi-Fi。

## 5. 手机—云端—屏幕—摄像头完整验收

1. **准备基准**：拍摄刷新前画面；选择与当前内容明显不同的测试图，包含可辨认的文字/色块/构图特征，避免同图重刷导致无法判断变化。
2. **手机实际操作**：用户在iPhone相册选图，进行双指缩放、拖动、任意角度旋转及裁剪，点确定生成抖动预览，记录预览截图和耗时。
3. **实际发起刷新**：由iPhone App点击刷新。记录云端任务ID、图像摘要和任务阶段，等待该任务的设备成功回报；不以脚本替代此次手机提交。
4. **实际画面核对**：刷新结束后，助手通过现有C270采集实拍，读取照片，对照该次手机预览检查主体、方向、裁剪边界、明显缺行或花屏；与刷新前照片比较确认内容改变。
5. **故障与恢复**：验证全新安装后无需输入任何连接资料即可联网，重启/断网后自动恢复；验证重复点击/重发不会重复执行同一任务、忙状态提示，以及覆盖安装/续签后连接配置保留。
6. **记录证据**：保存对应构建提交、手机/iOS版本、IPA摘要、任务ID、发送图像摘要、手机预览、前后实拍、设备结果及耗时。个人照片和凭据留在本地；公开文档仅发布适合公开的摘要或合成测试图。

摄像头核对属于助手读取实拍进行目视比对，不声称提供独立自动图像识别评分；软件成功回报和实物核对同时通过，才记录为完整闭环成功。如果相机视野不完整或曝光不合适，先调整再验收。

## 6. 实施顺序与验收边界

1. **本地准备与自动连接**：准备可公开的源码和合成测试图；在Flutter资产清单注册空连接配置资源，新增启动加载与安全保存逻辑。安装包内的有效私有配置优先应用，以便随更新同步变更；未注入的开发包沿用现有诊断配置方式。新增Ubuntu预处理脚本，只把云端地址和App访问凭证写入IPA，保持源码、公开产物及其他私钥不变。验证空配置、注入配置、首次启动、覆盖更新与日志脱敏。
2. **公开仓库与CI**：用户通过GitHub浏览器授权；先检查目标仓库再创建或复用，提交审核后的源码。建立固定工具链构建，运行检查与测试，产出并下载首个Release未签名IPA、摘要和构建记录；确认公开产物不含私人凭证。
3. **iPhone签名与安装**：配置Ubuntu设备服务及iloader；用户USB连接、信任电脑，在本机登录Apple账号。先本地注入连接配置，再签名安装；验证iPhone15Pro/iOS26.7.1独立启动、应用标识和覆盖更新。失败则保留IPA及脱敏诊断，不自动改用付费或无线安装路线。
4. **公网连通**：在云端构建等待期间排查443/8883及网络路由，确认手机可访问HTTPS、ESP通过MQTTS在线并能HTTPS下载。验收自动连接、断网恢复和Wi-Fi/蜂窝网络连接；不以SSH转发结果代替公网验收。
5. **真实手机闭环**：由用户在iPhone中实际选图、编辑和点击刷新；助手跟踪任务、接收设备结果，拍摄并核对刷新前后画面，至少完成一次与手机预览对应的实际刷新。
6. **更新、续签与交付**：当场重新签名覆盖安装一次，验证流程和配置保留，记录描述文件到期时间；提供每5～6天USB续签步骤，无代码改动时复用本地IPA。整理构建、安装、公网连通及摄像头验证记录，红米兼容性检查不阻塞iPhone主线验收。

交付物：公开仓库及Actions工作流、可下载的通用未签名IPA、保存在Ubuntu的已配置自用安装包、下载/配置注入辅助脚本、USB安装和续签说明、带任务ID与前后照片的验证记录。首次安装成功和完整业务闭环分别报告，不将其中一个当成另一个已经完成。

用户配合仅发生在必要环节：GitHub浏览器授权；iPhone插线/解锁/信任与开发者模式；本机Apple登录和验证码；手机选图/编辑/点击刷新；必要时调整摄像头角度。密码和验证码不发送到聊天。

日常开发循环为Ubuntu改代码→推送→云端构建→下载→本地签名安装→iPhone实测。首版不包含本地Xcode断点调试、常规Flutter热重载、TestFlight或App Store发布，也不消除免费账号7天期限。
