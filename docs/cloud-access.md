# 腾讯云公网端口设置

核对日期：2026-10-20。通过服务器实例元数据确认：

| 项目 | 值 |
| --- | --- |
| 产品 | 云服务器CVM |
| 地域 | 广州（ap-guangzhou） |
| 实例 | ins-jn8457i8 |
| 公网IPv4 | 42.194.237.249 |

## 控制台设置

1. 打开[云服务器控制台](https://console.cloud.tencent.com/cvm)，选择广州地域。
2. 找到公网IP为`42.194.237.249`的实例，进入实例详情的“安全组”页签。
3. 打开该实例已绑定的安全组，进入“修改规则 → 入站规则 → 添加规则”。如绑定多个安全组，先查看实例上的排序和已有拒绝规则，确保允许规则具有足够优先级。
4. 分别添加两条允许规则：

   | 类型 | 来源 | 协议端口 | 策略 | 备注 |
   | --- | --- | --- | --- | --- |
   | 自定义 | 0.0.0.0/0 | TCP:443 | 允许 | 墨间HTTPS |
   | 自定义 | 0.0.0.0/0 | TCP:8883 | 允许 | 墨间MQTT TLS |

   若界面将协议和端口分开，协议选TCP，端口分别填写443、8883。来源允许手机蜂窝、家庭Wi-Fi及相框Wi-Fi接入；服务继续验证项目CA和各自的访问凭据。

5. 保留原有规则。如果有“拒绝全部”规则，将新增允许规则放在其上方，保存即可；无需重启服务器。

依据：[腾讯云安全组规则及优先级](https://cloud.tencent.com/document/product/213/15377)、[查看规则](https://cloud.tencent.com/document/product/213/112621)、[修改规则](https://cloud.tencent.com/document/product/213/112622)。

## 保存后的验证

在Ubuntu项目根目录执行：

```bash
python3 tools/cloud_check.py
```

只有公网HTTPS健康检查、鉴权查询和ESP通过公网MQTTS上线都正常，才记为公网通过。此前SSH访问与服务器内部HTTPS检查正常，办公室Ubuntu直连TLS超时且服务器未收到对应流量；这只能定位到应用外的网络路径，不能仅据此断定安全组是唯一原因。

若设置后仍不通，可使用[实例端口验通](https://cloud.tencent.com/document/product/215/38836)检查入站TCP443、TCP8883，随后结合服务器抓包、Ubuntu网络路径排查。`python3 tools/cloud_check.py --ssh`仅用于检查云内服务，不代替公网验证。

## 2026-10-20验证结果

用户保存两条入站允许规则后，从办公室Ubuntu直接访问公网IP：HTTPS443的项目CA验证、`/health`与App鉴权查询均成功，MQTTS8883完成TLS1.3及证书验证，API显示ESP在线且不忙。随后公网脚本上传192000字节图像并刷新，34.77秒收到设备成功回报，UART为done且整图CRC一致。测试未使用SSH转发。摄像头全黑，实物核对、iPhone操作和手机蜂窝网络另行验收；任务及证据见[验证记录](verification.md)。
